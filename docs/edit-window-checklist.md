# 编辑与新增窗口检查清单

## 检查机制

### 一、编辑窗口检查项

#### 1. 数据一致性检查
- [ ] **打开窗口时显示的数据是否与数据库一致**
  - 检查方法：对比数据库中的实际值与窗口显示值
  - 重点关注：日期、金额、关联账户ID、基金代码、备注等
  - 注意：某些字段可能需要从关联表读取（如基金名称从FundEntry读取）

- [ ] **是否有遗漏字段**
  - 检查方法：对比数据库schema与编辑窗口显示的字段列表
  - 特别注意：新增字段是否已在编辑窗口中实现

#### 2. 保存写入检查
- [ ] **所有修改的数据是否成功写回数据库**
  - 检查方法：编辑后保存，然后查询数据库验证字段值
  - 重点关注：空值处理（清空字段是否正确写入null）
  - 注意：关联字段的处理（如linkId、linkType）

- [ ] **关联数据是否正确更新**
  - 检查方法：保存后检查关联表数据（如FundEntry、RegularInvestPlan）
  - 注意：双向关联的同步（TxRecord ↔ FundEntry）
- [ ] **基金批量编辑时费率/手续费是否联动回填**
  - 检查方法：批量修改手续费率或手续费后，重新打开同一批基金明细，确认手续费、份额和到账金额都已按最新值重算
  - 注意：手续费率只要变化，就应同时影响手续费和最终份额；单独修改手续费只影响下游份额/到账金额，不反算或保存新费率
- [ ] **投资交易编辑时是否遵守数据链触发边界**
  - 检查方法：打开已有基金/理财/股票等带份额、净值、数量、单价或手续费的记录，不操作费率直接保存，确认手续费和终点数量/份额不被自动重算覆盖
  - 注意：只有用户手动修改手续费率才允许重算手续费并联动份额/净额；手动修改手续费只联动下游结果，不反推费率
- [ ] **基金批量编辑时净值日期/入账日期是否按 T+N 输入**
  - 检查方法：批量修改净值日期或入账日期时，输入框应显示 T+N，保存后按每条记录的申请日和基金交易日历回放计算真实日期
  - 注意：这套规则应与导入预览窗口保持一致，不能在批量编辑里退回纯日期输入

#### 3. 打开入口检查
- [ ] 明细表中可编辑的记录应同时支持点击编辑按钮和双击整行打开编辑窗口
- [ ] 双击信用卡、保险、基金/理财/存款记录时，应进入与编辑按钮相同的专用编辑窗口并加载同一条记录
- [ ] 双击复选框、编辑、删除、获取净值等操作控件时，不应因行事件冒泡重复打开窗口
- [ ] 保存修改后，相关行、余额和汇总应刷新，但明细列表必须保留当前账户、页码、每页数量、筛选、排序和列设置；不得因为全局刷新或局部重拉数据而复位显示状态

### 二、新增窗口检查项

- [ ] 转账连续记账：点击“保存再记一笔”后保持窗口、日期、转出/转入账户和备注，清空金额并聚焦；延迟保存时快速连点或触发另一种保存只应提交一次，不能改变当前保存的关闭方式；保存失败后保留输入并允许重试。普通“保存”成功后仍关闭窗口。
- [ ] 连续记账成功后，鼠标留在“保存再记一笔”按钮处等待后台刷新完成，窗口必须保持打开；明细/账单分页参数同步、行定位参数清理不能被当作离开页面。真正切换账户、业务视图、账单月份或页面时仍应关闭窗口。

#### 1. 初始数据检查
- [ ] **是否正确获取关联数据库数据**
  - 资金账户列表：是否从数据库加载可选账户
  - 投资账户列表：是否正确筛选投资类型账户
  - 基金代码/名称：是否有自动获取机制
  - 默认值：是否设置合理的默认值（如今天的日期）

- [ ] **是否不应该全部用初始空白值**
  - 检查方法：哪些字段应该有默认值或下拉选项
  - 注意：某些字段如金额、基金代码应该为空（需要用户输入）

#### 2. 保存写入检查
- [ ] **所有数据是否全部写入成功**
  - 检查方法：保存后查询数据库验证所有字段
  - 重点关注：必填字段是否完整写入

- [ ] **关联数据是否写入成功**
  - 检查方法：检查关联表是否创建对应记录
  - 注意：linkId/linkType是否正确设置
  - 注意：双向关联是否建立（如FundEntry创建后TxRecord.linkId指向它）

### 三、字段特定检查

#### 基金名称字段
- [ ] 是否为只读状态（不可手动编辑）
- [ ] 是否根据基金代码自动获取
- [ ] 基金代码变化时是否触发自动获取（延迟800ms）
- [ ] 获取失败时是否有提示

#### 资金账户字段
- [ ] 编辑模式下是否正确显示已保存的资金账户
- [ ] 新增模式下是否有下拉选择列表
- [ ] 是否正确区分投资账户和资金账户
- [ ] 基金赎回、现金分红、红利再投必须使用申请日期持仓 SS 下拉选择基金；下拉候选按所选基金账户在申请日期当天及之前的交易回放得到，不能回退成自由输入基金代码
- [ ] 股票账户创建或编辑时，机构只能选择类型为证券/`brokerage` 的机构；校验通过后应自动确保同证券机构、同所有人、同币种下存在“证券资金账户”。股票交易窗口中，股票账户是持仓账户，证券资金账户是 `cashAccountId` 指向的现金/钱包类账户；资金账户下拉应使用 SS 并支持“新增资金账户”，已有资金账户候选不限制同机构，用户明确选择任意现金/借记卡/钱包资金账户都必须保留；新增时应显示当前股票账户继承来的所有人、证券机构和币种，并锁定这些归属字段，不能只让用户填写账户名称；同券商股票和基金可共用这一个资金账户，银证转账目标/来源也应是它
- [ ] 股票卖出不得使用自由股票代码输入框，必须使用 SS 下拉，并根据“交易日期”回放 `StockTransaction` 后只显示该日期有正数持股的股票；卖出数量不能超过当日可卖数量
- [ ] 股票分红必须先用交易日期持仓 SS 选择股票；现金分红填写分红金额并可选填写净到账，送股/转增填写新增股数并提交为 `bonus_share`，不能误生成现金流水
- [ ] 股票买入/卖出窗口应把交易日期、数量和成交价格放在同一行；成交金额只作为数量 × 成交价格的内部计算基础，不在窗口单独展示。费用项单独一行展示印花税、佣金、附加费和过户费，附加费汇总经手费、证管费、平台费、其他费用和旧兼容总费用字段；具体拆分可通过 hover 明细查看。最终行只读展示费用小计和金额合计，二者必须等宽、等高、同层级，并在标签或数值中明确显示币种（A 股为 CNY）。费用金额来自股票账户费率和市场默认规则，随数量、价格、代码、日期和账户变化自动计算，不在交易窗口手工编辑。“获取新费率”按钮应独立于费用小计和金额合计，不得改变二者布局；点击后刷新公开市场默认费率并重算预估。买卖交易弹窗不显示交割日期或券商成交号。保存时服务端再次按同一规则计算并写入 `StockTransaction`，买入资金侧现金流为成交金额 + 费用小计，卖出现金侧现金流为成交金额 - 费用小计
- [ ] 股票持仓表、持仓盈亏报表和股票交易明细表的股票名称/代码必须同一行展示，股票代码放在股票名称右侧；交易明细表的表头设置应能自选交割日期、股票账户、证券资金账户、市场、净额和各项费用拆分列
- [ ] 有翻页组件的表格，表头/列设置按钮必须固定在翻页组件右侧；交易弹窗股票名称回显只查本地证券、持仓和历史交易，不得为显示名称触发外部股票 API
- [ ] 股票交易明细支持编辑：双击明细行、点击行内编辑按钮，或从资金账户明细打开关联现金流水时，都应按 `EntryBusinessLink.stockTransactionId` 打开股票交易弹窗并预填动作、账户、日期、数量、价格、金额、备注；编辑态不读取费率、不显示费用预估区，保存走 `PATCH /api/v1/stocks/transactions?id=`，同步更新资金流水和 `StockHolding`，弹窗标题显示「编辑股票交易」
- [ ] 股票持仓盈亏报表页签读取当前 `StockHolding`，与股票账户持仓表共用同一套市值、成本、浮动盈亏、已实现收益数字；浮动盈亏 = 市值 - 成本，综合盈亏 = 浮动盈亏 + 已实现收益，不能从基金字段推断股票值
- [ ] 房产交易窗口不应显示基金份额、净值、确认日或到账日；购入、装修投入和出售只收集房产账户、资金账户、房产/名称、交易日期、金额、手续费、税费、市值和备注。手动更新市值应走单独估值保存路径，只更新 `PropertyValuation` 和 `PropertyAsset.marketValue`，不生成资金流水
- [ ] 导入预览表格中可修正的账户、日期、金额、费用、代码、备注等字段应支持双击就地编辑；股票导入预览的股票账户和银行账户应使用下拉/SS，交割日期批量修改应使用 T+N；编辑后必须重新执行预览识别、派生计算和阻断校验，阻断行可以被勾选用于批量修正，但确认导入前仍有阻断错误的行必须被拦截
- [ ] 导入预览窗口右上角已有关闭按钮时，底部操作区只保留右下角主按钮（确认导入/完成），不得再显示重复的取消按钮
- [ ] 导入预览中的“信用卡还款”是否保持业务类型显示，把付款账户限制为借记卡/电子钱包、目标账户限制为信用卡，并在落库后显示为“类型：转账、分类：信用卡还款”
- [ ] 导入预览中的普通转账和信用卡还款是否必须同时匹配本账户和对向账户；缺失或未匹配对向账户时必须阻断导入，不能按空值写库
- [ ] 普通账单是否逐行识别账户；信用卡账单是否只维护一个统一信用卡账户，并同步应用到全部预览行
- [ ] 只有机构和账户类型、没有后四位时，是否仅在唯一启用账户的情况下自动匹配
- [ ] 理财买入是否只显示资金来源同机构或同一所有人名下第三方支付/钱包机构的理财账户；新增产品后缺失的同机构理财账户是否自动建立、立即回填并在重新打开时保持一致

#### 标签字段
- [ ] 编辑模式下是否显示记录已关联的全部标签，包括系统/导入自动添加的全局标签
- [ ] 从记录上移除标签后保存，重新打开应保持已移除状态
- [ ] 标签下拉字典应包含当前账簿标签和全局系统标签，不能只因标签不在当前账簿字典中就隐藏已关联标签

#### 日期字段
- [ ] 编辑模式下是否显示已保存的日期（不被替换为当前日期）
- [ ] 新增模式下是否默认为当前日期
- [ ] 日期格式是否正确（YYYY-MM-DD）
- [ ] 基金、理财、保险、存款等赎回/退保/取出窗口是否同时回显和保存到账日期；业务日期、确认日期、到账日期、存款到期日不能互相覆盖

#### 金额字段
- [ ] 是否正确处理负数（买入为负，赎回为正）
- [ ] 普通转账编辑模式下金额是否显示正值；用户输入负值保存时，是否交换转出/转入账户方向后按正额落库
- [ ] 普通支出关联固定资产时，金额左侧固定资产开关应写入 `fixedAssetAccountId`，分类选择系统“固定资产”应直接打开固定资产账户创建窗口；保存、编辑金额/日期/账户、删除资金流水后，`PropertyTransaction` 和 `PropertyAsset.cost` 必须同步，人工估值不应被成本重算覆盖
- [ ] 是否正确处理小数位数

#### 信用卡分期字段
- [ ] 信用卡支出新增窗口显示“消费分期”；信用卡账单表头工具区显示“账单分期”，两个入口名称和来源不可混用；账单行内不再单独显示分期栏
- [ ] 分期金额大于 0 且不超过原支出，允许部分金额分期
- [ ] 账单分期金额默认参考该期未还金额，但不限制输入上限；冲抵来源账单；首期本金和手续费的账期按首期入账日期和账单日计算
- [ ] 账单分期窗口应允许输入分期确定日期，保存为冲抵行日期；日期不强制限制在来源账单周期内，并按该日期和账单日自动归属来源账单
- [ ] 账单分期应使用系统支出分类“银行分期”；冲抵行按账单计算专用规则冲抵来源账单，不能让账单金额反向增加
- [ ] 分期生成的每期扣款日期应按首期入账日期逐月推进，首期入账日期默认等于分期日期但可单独指定；每期本金和手续费/利息应拆成同日两条流水，备注注明原始分期日期
- [ ] 信用卡账单摘要表应显示“流出”“流入”“本期金额”列；流出/流入按信用卡视角的金额正负统计，不按收支大类统计，本期金额口径为流出减流入
- [ ] 手工修改信用卡账单周期后，周期日期应写入 `CreditCardCycle` 并标记为人工周期；后续交易、分期或金额重算后重新打开同一期，周期开始/结束日期不能被 `Account.billingDay` 重新推导覆盖
- [ ] 期数限制为 2 至 120；费率明确区分年利率与每期手续费率
- [ ] 保存后原消费、冲抵行和各期明细使用同一个分期计划 ID
- [ ] 删除/恢复原消费或任一分期生成行时，冲抵和各期明细必须整体联动

#### 贷款和消费分期
- [ ] 普通借入借出窗口不显示 `资金到账/消费分期` 选择；新建借入默认是资金到账，必须增加所选入账账户余额
- [ ] `消费分期` 属于支出/信用卡消费分期流程，不应靠借入借出窗口或账户名称自动推断生成
- [ ] 历史 `debt_financed_purchase` 记录编辑时应保持兼容回显和保存，不得因隐藏入口而被误转成普通借入
- [ ] 保存银行贷款时只创建贷款负债和计划任务，不能补生成未来还款交易；还款交易必须由计划任务到期执行生成
- [ ] 新建银行贷款时，自动扣款应显示扣款日和扣款账户，非自动扣款应显示账单日和最迟还款日；同时显示期数和每期计划明细，每期明细至少包含适用日期、本金、年利率、利息和应还合计，并能按利率调整草稿实时更新
- [ ] 贷款窗口「放款/借入」按贷款类型区分现金含义：消费贷和房贷是直接消费，不显示入账账户，贷款资金不进入资金账户（`toAccountId = null`）；抵押贷款是以固定资产抵押取得资金，必须选择入账账户并形成资金流入。消费贷开立页保存时先生成账单/分期出账计划（`loanPlanRole = bill`，`autoDebit = false`），自动扣款打开时必须填写扣款日和扣款账户，并额外生成自动扣款计划（`loanPlanRole = auto_debit`，`autoDebit = true`）。房贷不提供自动扣款开关，固定还款区必须直接填写扣款日和还款资金账户，保存时按 `loanPlanRole = auto_debit` / `autoDebit = true` 处理；抵押贷款的自动扣款默认关闭，打开后才显示扣款日和扣款账户；还款/提前还款仍显示资金账户（扣款账户）。
- [ ] 房贷窗口不需要填写用途分类；仅消费贷款保留用途分类。消费贷款和房贷顶部布局一致：发生日期右侧是贷款机构，下一行是贷款账户和贷款总额，不显示入账账户。抵押贷款顶部布局固定为：发生日期 + 贷款机构、贷款账户 + 入账账户、固定资产下拉、贷款总额 + 标签、还款方式 + 总期数 + 年利率；抵押贷款不显示固定资产开关，不使用“抵押物”文案，不显示 LPR 折扣/获取按钮或利率调整行。消费贷款的用途分类、固定资产关联开关和还款方式放在同一行；自动扣款显示扣款日和扣款账户，非自动扣款显示账单日和最迟还款日。只要贷款总额、总期数和适用的还款/扣款日期有效，就显示“分期计划预览”，年利率为空或 0 时按 0 利率预览/保存。消费贷款利率调整只维护生效日期和年利率，并即时影响分期预览；消费贷款视图的利率调整只用表格展示，首行显示贷款日期和起始利率（即使为 0），非编辑行右侧提供编辑/删除，新行默认当前日期并进入编辑态，编辑态右侧只显示“保存”，行内保存后再显示编辑/删除；底部整体保存后提示是否从最早变更日期重算还款表，弹窗底部不显示重复取消按钮，交易明细表头不显示单独重算按钮；保存后影响生效日之后的还款表和后续自动还款，且不显示 LPR 生成区。房贷保留固定资产关联、LPR 折扣/获取按钮和历史利率调整入口，不显示银行执行利率组件。“获取”应按贷款发生日取人行基准/LPR 派生年利率；历史 LPR 调整应按合同年度重定价日套用当时有效的 5 年期以上 LPR，不能按每月 LPR 发布日生成不存在的银行扣款变化，也不能要求用户手工填写历史过程。
- [ ] 贷款弹窗主标题应显示“贷款”，不得再显示“往来款”；同一弹窗内的“消费贷款”“房贷”“抵押贷款”必须是明确子页，切换后字段组必须不同，不能只换个标签。
- [ ] 贷款还款/提前还款页只能用贷款账户下拉选择，不能手输或先选机构/往来对象；下拉必须按还款日期动态筛选，只显示该日期仍有欠款本金余额的机构贷款账户，日期切换后无余额的已选账户要清空，保存端要用同一口径兜底校验。
- [ ] 贷款还款/提前还款编辑事件可以携带 `loanType` 作为筛选或元数据，但窗口打开必须以保存的 `mode` 为准；正常还款和提前还款都应停留在还款页签，不能因为 `loanType` 被误切到房贷、抵押贷款等贷款开立页。
- [ ] 贷款还款选择账户后，应按还款表当期带出剩余本金、剩余利息和本息合计；保存的正常还款必须写入对应 `regularInvestPlanId` 和 `installmentNo`。只有该期关联实际转入累计达到应还合计时才显示“本期已经还清”，部分转入不得误报已还清，`loan_bill` 账单不得计作还款。
- [ ] 提前还款必须作为独立事件显示，减少后续还款计划的剩余本金，但不能占用或递增普通月供期次；重算只更新 `RegularInvestPlan` 的后续计划字段，不改写、删除或补生成已经发生的真实还款流水。
- [ ] 建立和编辑贷款时，贷款名称、关联原始贷款记录的本金、总期数和利率应完整回显并可修改。自动扣款只填写扣款日和扣款账户；非自动扣款分别填写账单日和最迟还款日。保存后重开应与数据库一致，且不得改写或删除已经发生的真实还款流水。
- [ ] 往来款贷款列表双击银行贷款行时，应打开账户编辑窗口，并在其下方回显、编辑原始贷款记录与主还款计划字段；不得改为弹出原始贷款交易编辑窗口。普通往来账户窗口仍只显示账户基础资料。

### 四、表结构映射检查

#### TxRecord 表字段（基础交易）
**存在的字段**：
- `type`, `date`, `postedAt`, `accountId`, `accountName`, `amount`
- `toAccountId`, `toAccountName`
- `categoryId`, `categoryName`
- `fundCode`, `fundProductType`, `note`
- 贵金属交易额外字段：`metalTypeId`, `metalTypeName`, `metalUnitId`, `metalUnitName`, `metalQuantity`, `metalUnitPrice`, `metalFee`
- `linkId`, `linkType`
- `statementMonth`, `deletedAt`

**不存在的字段（易错）**：
- ❌ `fundSubtype`（属于 FundEntry）
- ❌ `fundUnits`（属于 FundEntry）
- ❌ `fundNav`（属于 FundEntry）
- ❌ `fundFee`（属于 FundEntry）
- ❌ `fundConfirmDate`（属于 FundEntry）
- ❌ `fundCashAccountId`（属于 FundEntry）

#### FundEntry 表字段（基金明细）
**存在的字段**：
- `accountId`, `accountName`
- `fundCode`, `fundName`, `fundSubtype`, `fundProductType`
- `amount`, `fundUnits`, `fundNav`, `fundFee`
- `fundConfirmDate`, `fundCashAccountId`
- `linkId`（指向 TxRecord）
- `memo`

#### 投资交易账户结构
- `TxRecord.accountId` = 资金来源账户（现金账户）
- `TxRecord.toAccountId` = 基金账户（投资账户）
- `amount` 为负数 = 买入（资金从左流向右）
- `amount` 为正数 = 赎回（资金从右流向左）
